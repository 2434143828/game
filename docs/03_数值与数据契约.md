# 数值、状态与数据契约｜v0.1

## 1. 配置源与单位

| 文件 | 内容 |
|---|---|
| game.json | 全局边界、费用、时钟、员工、布局、日终与存档 |
| days.json | 三日目标、开放角色、员工ID与简报 |
| anomalies.json | 五个对象、15条工作、五条特殊规则、敌方行为与唯一联动 |
| equipment.json | 5专属+1制式武器、5专属+1制式防具 |
| skills.json | 5技能的目标、消耗、冷却与效果 |
| localization.zh-CN.json | 玩家界面基本文案 |
| assets.json | 缺省占位素材、状态与音效清单 |
| facility.json | 2026-10-20扩展：大地图世界边界、相机、房间/大厅、节点/连接与空闲散步参数 |

原七份玩法配置保持；默认设施改用 `facility.json` 的真实世界图，不再把 `game.layout` 的旧单排坐标映射到新图。旧两人回归入口仍使用旧布局。运行时位置新增 TRANSIT、floorId、segmentId，以区分竖向通路及几何相交但不连通的路径；这些不是日初存档字段。大地图与旧地图共用固定步长、工作/伤害、经济和日初存档协议。

秒用Sec后缀，距离用Px，速度用PxPerSec。能量为整数，伤害、生命、精神、压力使用非负浮点数；显示可以舍入，逻辑不提前取整。比例统一存0—1，例如0.04是4%，不得存4。承伤倍率不是减伤率：0.6意味着实际承受60%基础伤害。

所有配置加载失败必须报告文件和字段路径。不得静默用0填充失效字段。数组顺序不代表业务优先级；使用稳定ID关联。

## 2. ID与状态

收容物N01—N05；武器W00—W05；防具A00—A05；技能S01—S05；员工内部ID为E01—E06，显示编号为A-01—A-06，避免和防具ID混淆。所有关联都必须存在，且符合来源一致性。

房间基础状态只有LOCKED（未开放）、CONTAINED（收容中）、BREACHED（失效）、RECOVERING（恢复）。作业不是额外的房间基础状态；房间收容中且有执行阶段的工作，UI才显示“作业中”。因此联动对“收容中的大狗”必须包括正在作业的大狗。

工作对象WorkRuntime有TRAVELLING（预约且前往）、EXECUTING（已到位作业）两阶段。房间最多有一个WorkRuntime，员工最多执行一个命令，结束或取消时双向关联一并释放。不能只清员工而房间永远占用。

游戏阶段为MENU、DAY_PREP、RUNNING、DAY_REPORT、FAILED、COMPLETE。战术暂停通过timeScale=0表达，不把状态改成一个会丢失RUNNING上下文的复杂分支。弹窗暂停原因单独记集合；关闭弹窗后只有在没有其他暂停原因且此前不是手动暂停时才恢复。

## 3. 工作结算事务

对同一固定步到期的工作使用两阶段处理，不能按员工数组从头到尾边算边加钱：

1. 移动/攻击先结算；广播、中断、惊慌/重伤先清理无效工作。到期但已被中断者不再承受“完成损伤”。
2. 对剩下的到期工作计算完成损伤。若因此惊慌/重伤，按紧急中断处理：无产能；房间仍收容时仅+8压力，不再加该工作的正常压力与特殊罚值。该次不更新成功完成记录。
3. 对人员仍有效的到期工作应用基础压力与特殊规则，更新完成记录；记录候选收入，暂不入账。因压力达到100而失效也视为完成过本次过程，但没有收入。
4. 合并全部达到阈值的房间，按N01→N05稳定顺序进入失效，触发必要的N04→N03联动，处理联动再次造成的失效，直到没有新增事件。仅一条边，无任意组合模拟。
5. 对仍收容、人员仍有效、没有被失效取消的候选工作同时入账并释放工作对象。所有候选都处理完才向UI发布产能事件。
6. 事件幂等：workId对应的能量最多入账一次；breachInstanceId对应的联动最多处理一次。

当玩家暂停时直接施放技能，命令使用同一套伤害与失效/重新收容函数即时执行并清理无效目标；不要先把视觉播放成功，等解暂停后才偷偷校验扣费。

## 4. 特殊规则记忆字段

| 字段 | 用途 | 何时改变 |
|---|---|---|
| lastCompletedWorkType | 奶龙连续互动 | 正常完成过程后更新；主动取消/紧急中断不改 |
| lastCompletedEmployeeId | 耄耋轮换 | 完成过程后更新；实际无作业满20秒清空 |
| lastCompletedAtSec | 大狗工作间隔 | 完成过程后更新；开工时取该时间锁定rapidRestart标记 |
| nonSootheCount | 叮咚鸡三次非安抚 | 非安抚完成+1；到3触发并归零；安抚归零 |
| idleElapsedSec | 耄耋休息/N05空闲 | 未EXECUTING时累计；N05完成过程清零，工作中冻结；取消不清零 |
| pendingForcedHowl | 大狗联动吠叫 | 布尔值，最多一个；正在蓄力不再叠加 |

N02的空闲休息在一次工作结束或中断后从0重新计算；N05则保留未完成前的空闲累积，直到完成一次过程或日初/恢复重置。不要因为共用一个字段而把两个规则的重置条件混成同一套。

N05越过30秒边界的增压量按区间计算：`rate × (max(0, newIdle−30) − max(0, oldIdle−30))`，防止跨阈值的一步多计整段时间；仍只在未实际作业时推进idle。

## 5. 伤害与攻击时序

固定伤害只允许RED、WHITE、BLACK；比例伤害在本版只允许PALE。DamageSpec区分FLAT与MAX_RATIO，不能靠读取同一个amount再猜单位。

员工承受黑伤分别扣生命和精神，敌人单镇压条仅扣一次。工作损伤读取员工防具倍率，技能攻击读取目标倍率；技能不读取随便一名员工的武器。

attackPeriodSec定义两次攻击“开始前摇”的最短间隔，包含本次前摇，不是前摇结束后再额外等待一整段。移动型敌人在前摇时停止移动；命中时重新检查目标是否仍有效、位置是否仍在范围内。射程之外取消这次命中，但该次周期仍被消耗。

控制或击退取消未命中的前摇：普通下次前摇时间重置为控制结束（击退则当时）+完整攻击周期。待执行的唯一联动吠叫按联动规则处理。造成伤害的同一hitId不得重复计算。

员工单位普通攻击同样在前摇结束校验射程。远程弹道只是表现，不使用渲染粒子回调扣血。所有异常只攻击走廊，N04广播例外可攻击设施内非安全室目标。

## 6. 购买、装备与施法事务

购买顺序为：校验来源已开放、前置完成、未购买、钱包充足→一次扣费并更新解锁/库存→发出一次事件。每物装备开发只产生一份武器实例与一份防具实例，解锁标志阻止重复生成。

将专属装备分配给另一员工，要同时校验新旧持有人可换装。一次事务中从旧槽卸下、为旧持有人恢复制式装备、把专属实例给新持有人，再发布结果；不能出现同一实例在两人身上或丢失。制式装备无需实际无限实例表，可通过缺省槽位表示。

施法校验阶段不改变世界；成功提交时扣费、置冷却和产生效果为一笔事务。重复命令ID直接返回已处理结果；不能因双击同一帧多扣费。独立两次输入仍受冷却阻止。无目标范围技能不消耗，恢复范围至少包含一名可恢复SP的员工。

## 7. 生命周期清理

进入失效：取消该房工作/预约；隐藏收容形象；创建唯一主样本及允许的分身；原作业员工沿支路撤出（仍在房间内时不受一般走廊攻击，但可能受广播）；触发一次事件；禁止新工作。

主样本镇压值0：主样本消失；清除该实例分身、前摇和待发攻击；关联员工失去目标后待命；房间进入10秒RECOVERING。恢复期不存在可攻击实体或能量来源；结束后压力25、规则记忆归零。

进入日结算/失败：冻结全部模拟，清理延迟攻击与待入账任务。切次日重新建现场状态，不能复用旧定时器。先完成存档事务再显示下一日准备，避免重复发人。

## 8. 存档与版本

存档为JSON，带schemaVersion=1、designVersion和saveBoundary。包含当日日初准备入口的持久状态快照，不包含Phaser对象、定时器句柄、DOM（网页元素）或函数。

只保存日初入口快照意味着“本日在准备界面购买然后重试”也会回退购买。新日入口已承接上一日结余，所以不会把上一日购买清除。完成标记与日初快照分别存储，第三日完成后不再次开始该日。

存档读取先验证ID、数值范围和一件装备只有一个持有者，再接入世界。格式错误保留原文并给用户显式新建选项。

## 9. 运行记录与测试范围

validation/validate_design.py检查JSON结构、引用、类型约束和关键范围；validation/test_balance_math.py对本规格公式及账面例子执行测试。它们不能证明Phaser实现的效果正确。

Codex必须另外给实现写同名业务测试或等价用例，并在真实运行中覆盖暂停、移动、工作到达、目标失效、广播同帧、保存/重试等场景。
