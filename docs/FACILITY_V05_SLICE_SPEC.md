# v0.5 基地环境美术垂直切片规范

更新：2026-10-25。本轮范围为 N01 奶龙收容室、SAFE 医疗休憩区、N01 门侧至 A-top 的连接走廊，以及 SAFE 入口接缝。只更换这三个样板区域的环境表现，不批量替换其他房间。本文取代先前“在旧房间壳体内叠放样板图片”的临时方案。

## 风格问题与修正

实际场景使用 `architecture.ts` 的 `drawGeneratedArchitecture()` 和 `EnvironmentArt`，不是只靠程序绘制 fallback。旧的墙面、房间壳体、地板、机械门框、灯具及设备有较密的金属纹理与高光边缘；员工使用 `HumanRig` 和 `personnel-v3` 分件，收容物使用 `CreatureRig`，更接近平涂、简化轮廓。材质、细节密度和比例都不一致。

早期样板只是盖住内墙，旧地板、边框、设备脚和灯仍露在外面；走廊图片底部与真实脚线不重合。这些原因不能靠调色或 CSS 滤镜解决。具体资源映射、尺度及组件契约见 [组件规范](FACILITY_V05_COMPONENT_RULES.md)。

最终样板以暖白墙、鼠尾草护墙带、深灰手绘结构线和有限明暗为基础。观察窗、终端、医疗床、药柜和长椅解释区域功能。低细节墙面给角色留出视觉空间，保持现代异常收容机构设定。

三张源图均为 `1983×793`。源图中的额外底部地板在渲染时裁去，裁切高度分别为 734、764、735；代码绘制的承重面从真实导航脚线往下延伸，避免出现第二条地板。生成提示词保存在 `public/art/facility-v05-slice/generation-final.json`。早期试稿保留，已经不作为最终样板加载。

`FacilitySliceArt.ts` 接管样板范围的墙、地板、框、门与静态道具。旧壳体、桥面、设备和灯在这些范围内跳过绘制；范围外继续原资源。门叶是独立绘制对象，继续注册真实房间 ID，开关读取实际状态；没有在背景中烘焙角色或功能门。SAFE 门沿用原来的员工接近表现。缺失任一新纹理时，三个样板一起回退旧环境，避免空白或新旧组件混搭。医疗区标题向右下避开上层既有地板，避免被旧结构覆盖。

## 可复用规则

- 结构外轮廓为 2–2.5 world px，内部分割为 1–1.5；缩放前后都检查，不能只看源图精细度。
- 每物件使用底色、单层阴影与少量局部亮面，保持 2–3 档；不使用连续金属高光、密集铆钉和管网。
- 墙面、设备和框的对比低于活动角色；角色通行带后方保留连续低细节块面。
- 门、地板、房间和走廊使用原地图锚点；不移动角色、工作位或导航节点来迁就图片。
- 门框、门叶、地板单独绘制；背景只含静态墙面和识别性道具。
- 床、药柜、终端按员工尺度验收；现代机构功能优先，避免温室、废土、军事或蒸汽朋克特征。

完整组件尺寸、色板与禁止项见 [组件规范](FACILITY_V05_COMPONENT_RULES.md)。本轮形成的是三处样板和可复用契约，不是全基地组件库。

## 验证与边界

实际运行的三组同镜头前后图、整合图、连续改令/暂停记录和检查结果见 [验收记录](FACILITY_V05_ACCEPTANCE.md)；[前后对比浏览页](art-style-v05/facility-slice-review/comparison.html) 集中呈现正式截图。对比通过 DEV 专用 `facilityArt=legacy` 切换旧环境绘制，场景与角色仍是真实游戏；这比不同时期的历史截图更适合判断本次变化。

本轮未改玩法、导航、战斗、E.G.O.、数值配置或存档格式。发现的原有 V3 直接点击 SAFE/ROOM 移动限制单独记录，未借美术任务改动模拟层。因此不能把本次走廊移动验证写成完整“进室工作→回医疗区”验证，也不能宣称全基地或全部游戏流程验收完成。样板扩展需先取得对这套视觉方向的验收结论。
