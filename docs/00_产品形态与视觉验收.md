# 先验收游戏形态：二维设施模拟经营｜v0.2

**这是所有开发任务的前置要求。** 本项目参考《脑叶公司》的2D设施剖面、员工空间调度、实时工作与镇压体验。不是“采用相同数值规则的文字小游戏”，也不是收容物卡片管理网站。

用户已经明确否定网页文字小游戏的交付形态。以下视觉与交互要求必须进入第一轮实现，而不能留到“数值全部完成以后再补美术”。本文件不增加新玩法或商业化系统。

2026-10-20 用户追加要求：扩大设施、打破整齐单排布局、空闲员工散步，并继续参考《脑叶公司》的设施空间感。因此下文“原版地图距离不变/固定单屏”的早期默认由 DECISIONS D18—D20 覆盖：使用一张更大的固定多层设施图和可操作镜头，仍是原五物，不新增自由建造、动态楼层或电梯系统。其余真实实体、直接调度、动作和实机验收要求继续适用。

## 1. 先看验收结论

打开游戏并开始第一天，玩家应当直接看见一座二维收容设施。员工是站在地板上的小人，收容物是待在房间里的角色。下达工作命令后，小人沿通道走进房间；失效后，异常实体出现在走廊；玩家在同一场景中点选人员，调动、攻击、撤退、施放技能。

**即使收起员工详情和事件日志，玩家仍能进行基本调度，并看懂有人在走路、有人在工作、哪里正在失控。** 精确数值与规则说明可以依赖界面文字；本要求不是删除所有文字，而是不许用文字代替场景。

浏览器是允许沿用的开发载体，不是已经确认的最终发行平台。网页打开不等于文字游戏；改引擎或打包成桌面程序，也不自动等于满足本要求。先修正游戏本体。

## 2. 画面构成：设施是主体，面板是辅助

使用二维侧视剖面式室内表现。可以将固定设施展开显示，以方便管理，但不能画成鸟瞰战略地图、连接节点示意图、五列信息卡或静态背景海报。

固定设施继续使用原来的五间收容室、走廊和安全室，不新增自由建造、动态楼层、电梯系统或第二套地图。现有逻辑节点可保留；竖向支路也必须画成设施内的可通行连接区域，不能只画一条抽象连线，也不能用传送省掉移动。

每间收容室至少有可读的墙体/地板结构、房门或观察窗、室内设备、工作人员站位和收容物站位。房间有连续的设施关系，不是互不相干的五张卡片。未开放房间表现为实体空间封闭，仍属于设施。

主设施视区至少占默认画幅约65%；不能靠空白画布凑面积。设施主体横向覆盖主视区的大部分区域，房间、员工和异常不能缩成一条很小的示意图。顶栏放日指标和暂停；右侧放紧凑的人员/选择详情；底部放五技能。日志默认折叠或只占小块区域，展开后再看完整八条。

v0.2显示默认：1600×900；设施视区(16,76,1328,720)，右侧详情起点x=1360，底部技能栏起点y=808。缩放至1280×720时仍须可读，不滚动网页访问游戏。上述是实现默认，可按实际可读性微调，但不能反过来把设施缩成面板上的小装饰。

逻辑位置与显示位置之间需要统一映射；鼠标选取、技能范围、前摇提示和人物脚底使用同一映射。保留原版地图距离与速度，不为塞进界面擅自改动战斗射程与走路时间。

## 3. 占位美术不等于省略美术

第一版允许代码绘制，不要求正式贴图、复杂逐帧动画或购买美术包。但必须有：

- 员工：清楚的头、躯干、四肢和制服轮廓，脚底落在地面，手持武器可见。默认高度约56—72逻辑像素；不能只用圆点、编号矩形或头像代替整个世界实体。
- 收容物：五种明显不同的角色轮廓，室内与失效状态一致可追踪。没有正式参考的形象明确标注为概念占位，不声称官方还原。不能五个相同圆球只改名字和颜色。
- 设施：统一的工业内部场景，门、灯、观察窗、工作设备与安全室的用途有视觉区别。不需要写实材质，但必须看得出员工身处室内。
- 武器、防具：复用员工基底，通过手持武器轮廓、制服局部饰件或配色显示差别，不要求六套重做角色，也不新增装备被动。

不能因为没有角色原图，就将实体替换成一行“奶龙：收容中”。资源加载失败可以临时回退警示图标以避免崩溃，但这种降级状态不算视觉验收通过。

风格定位是严肃工业设施与荒诞收容物的反差。此前宣传片的粒子、黑金大字和规则怪谈片头，不是主游戏界面参考。

## 4. 必须发生在场景里的动作

| 行为 | 玩家必须看见 | 不接受的替代 |
|---|---|---|
| 选择员工 | 点击小人出现脚底选中圈/轮廓；能拖框多选 | 只能从下拉框选择员工 |
| 下达移动 | 在走廊给出目的地，小人转向并沿通道连续走过去 | 改“所在位置”字段、瞬间传送、列表刷新 |
| 派遣工作 | 点房间选择工作，员工抵达工作位后才开始；人在室内作业 | 远程点击观察按钮就直接倒计时 |
| 作业与产能 | 员工有记录/互动/安抚姿态，室内有反应；实际完成时能量反馈 | 只显示进度条，没有人员和房间活动 |
| 失效 | 房间警戒灯/门状态改变；室内形象撤下，真实敌方实体在走廊活动；该物停产 | 卡片由绿变红后弹出一个“镇压”按钮 |
| 奶龙分身 | 主样本与两只分身分别处于场景位置，可选中、可受击；主样本明确标记 | 数字写“敌人×3”，场景只有一个图标 |
| 镇压 | 员工接近射程后出手，武器/声波/击打效果与受击反馈对应；移动和距离影响命中 | 按一下按钮直接扣镇压值或自动播放预设战斗 |
| 危险预警 | 受击范围绘在单位所在走廊，前摇期间能移动避开 | 只有日志提示“即将受到范围伤害” |
| 技能 | 世界内目标高亮或范围预览，施放后控制/位移/恢复确实作用于对象 | 只更新技能卡数字或播放无目标特效 |
| 撤离恢复 | 员工停止追击、沿路进安全室，抵达后才恢复 | 点击恢复后远程瞬间回满 |
| 暂停 | 位移、工作、攻击、危险前摇和表现中的动作一起停下，可重新下令 | 数据暂停但小人还在走或仍演出命中 |

选中动画、按钮悬停可以使用非模拟时间；人物运动、作业和攻击表现须服从模拟暂停。命中结算来自模拟事件，不来自动画播放完毕回调。占位动作可由分部件旋转、位移和缩放实现，但要表达动作，而不是全靠整体闪烁。

技能立即生效、暂停时可下令等规则仍按主规格执行；不要求新增物理引擎、刚体碰撞或弹道系统。

## 5. 重构已有文字版本，而不是继续为它加内容

先查看现有代码与本地改动。保留可复用的配置、存档、数值、工作/伤害函数和测试；不要清空仓库、覆盖用户存档、回退用户改动或擅自改用另一套引擎。

如果已有的世界状态真的包含位置、路径、实体与时间，可以直接接入场景绘制。若现有逻辑只是点击按钮就结算，必须补上移动和作业等必要状态，不能仅在旧页面旁边添一个播放动画的画布。

所有世界内指令和辅助面板指令，调用同一套命令入口和状态机。每个小人/怪物的显示对象绑定同一个真实实体编号；选择、位置、伤害、目标和日志不可各自维护一套假状态。

现有网页界面组件可以继续用于设置、档案和装备，不承担主要世界模拟。若原项目尚未采用引擎，可按旧版锁定的Phaser（二维游戏框架）方案建立真实场景；若已有可运行二维引擎，不为文档偏好迁移。开发时核对实际依赖，不将“安装了框架”当作交付完成。

## 6. 先做一间，再接五间

**M0第一关：** 只需一间奶龙收容室、连续走廊、安全室和两名员工；有实际场景、可见角色、连续移动、点选/框选、暂停与改令。这是独立调试场景，不修改正式日1的四员工配置。不得用菜单、百科、五个卡片占位宣称完成M0。

**M1第二关：** 在相同场景里完成派遣→抵达→作业→产能→真实失效→战斗→撤离恢复→重新收容。然后接回正式日1配置。小闭环已具备最低视觉标准，才能扩展另外四种收容物、三日内容、装备和技能。

M5只是补充音效、改善美术一致性与完整回归，不是第一次添加场景和人物的阶段。

## 7. 视觉与交互验收 V01—V12

以下均未执行；必须由实际游戏运行验证，不能以本规格文字或模拟层单元测试代替。

| ID | 实际检查 | 通过条件 |
|---|---|---|
| V01 | 进入日1，截图 | 主画面是设施剖面和场内角色，不是网站卡片列表；设施视区约65%以上 |
| V02 | 缩至1280×720，关闭详情与日志 | 仍看得清房间、员工、异常和工作/失效；可直接点选和调度 |
| V03 | 在场景点击、Shift加选及框选员工 | 选中反馈与受命员工一致，不依赖员工下拉框 |
| V04 | 给工作命令，半路暂停再改为撤退 | 只在恢复后向新目的地移动；取消工作不入账；非预录路线 |
| V05 | 先让远处员工工作，再让近处员工工作 | 均抵达才计时；行程时间确实不同；作业姿态在室内 |
| V06 | 触发一次奶龙失效并继续游戏 | 一主两分身是独立可选实体；房间停产；其他房间可继续工作 |
| V07 | 镇压时下撤退命令 | 角色先接近射程再攻击；撤退停止追击且路径可见；不是后台定额扣血 |
| V08 | 大狗蓄力时走出范围 | 世界范围预警位置正确；按实际命中位置避伤；没有仅在日志里发生的攻击 |
| V09 | 施放控制、击退、精神恢复 | 对应目标发生冻结/位移/恢复，状态与画面同步，非纯粒子表演 |
| V10 | 暂停时查看工作、移动和攻击 | 模拟及关联动作不推进；允许瞄准、改令等界面响应 |
| V11 | 换装并再次出战 | 场内武器/制服局部有差别；伤害/抗性仍按配置，不新增特效被动 |
| V12 | 给出一段连续交互演示及实际命令记录 | 包含走路途中改令、进室作业、失效镇压；静态概念图或一张截图不替代动作验收 |

V01—V04在M0检查，V05—V07与V10在M1检查，其余在相应内容接入后检查。第一阶段不要求先做完三天。

演示优先使用真实操作录屏；环境不能录屏时，可以使用同一次实际操作的连续截图与相应事件记录，说明没有视频。环境完全不能运行则标注“未验证”，不得假造截图或声称已试玩。

最终判定：功能测试通过但V项未通过，仍不是用户要求的游戏交付。
