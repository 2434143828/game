# 开发任务与验收｜v0.2

这是待开发游戏的验收清单。本文列出的用例不是已经执行成功的游戏测试；设计包中实际执行的仅为配置检查与公式例算，见validation目录。

## 0. 先通过产品形态验收

`00_产品形态与视觉验收.md`的V01—V12是本表前置及并行验收。原73条逻辑用例保留，但文字版把这些跑通也不能算合格。先做真实二维设施、可直接操作的小人和场景动作，再增加内容；M5不负责第一次补上游戏画面。

## 1. 阶段顺序

| 阶段 | 实施内容 | 必须看到的可操作结果 | 禁止跳过的验证 |
|---|---|---|---|
| M0 二维场景与输入 | 检查可复用工程；一间收容室、走廊、安全室、两小人的调试场景；真实角色、连续空间与点选/框选 | 直接点小人并移动；半路暂停、改令、恢复；不是卡片或自动播放 | V01—V04；配置、类型、构建及屏幕适配。正式日1仍四人 |
| M1 可视奶龙完整闭环 | 进室作业/动作、压力产能、真实失效主从实体、追击/出手/受击、安全室恢复、日结算 | 员工从行走到室内作业；异常在走廊活动；现场镇压和撤退；接回正式日1人数 | V05—V07、V10；失效零产能、暂停、同帧顺序、主从清除及达标退出 |
| M2 五物与四伤害 | 四个剩余对象；独特工作条件；范围前摇；惊慌/重伤；红白黑苍白统一公式 | 五物不是只改名称；分别能展示独特工作代价与失效行为 | 黑伤双损、苍白按最大值、广播中断、空闲计时不被取消刷掉 |
| M3 研究装备技能 | 档案购买、专属装备唯一实例、装备转移、五技能、范围选点与冷却 | 换装真正改变伤害；技能改变实体状态，而非只播放特效 | 资源扣除原子性、无效施法不扣费、暂停冻结冷却、装备无被动 |
| M4 三日与唯一联动 | 日1→日3开放；一次可跳过教学；叮咚鸡→大狗；日初快照、重试、完成页 | 新档可完整玩三日，重试不刷资源，联动只触发一次 | 同步工作/失效的入账顺序、日终带事故、恢复边界与存档一致性 |
| M5 体验与交付 | 可读UI、音效、占位资源管理、错误反馈、帧率与全流程回归 | 非开发者不用控制台可理解并通关；给出真实启动方法和验证记录 | 最低分辨率、30/60/144帧等价、后台暂停、缺资源降级、无权限请求 |

每阶段更新根目录STATUS.md，至少记录“实现内容、实际运行命令、结果、未验证项”。M0是场景与操作的第一验收点，M1是规则和画面结合的第二验收点。先完成一组角色的最低可读美术及真实动作，不先堆五物立绘，也不能先把全部数值写完再补场景。

## 2. 开发测试入口

开发环境提供调试面板或纯模拟测试夹具，可设置房间压力、触发指定失效、创建员工状态、读取钱包、跳至某日准备。正式构建不暴露直接改业务状态的调试按钮。

调试事件必须走正式的失效/伤害/产能函数，不能另写一份“测试专用假行为”。所有能量、伤害、命令和联动使用可追踪事件号。

以下用例除专门标注以外，先在模拟层测试，再选择代表性场景做浏览器操作验证。浮点结果允许1e-6误差。配置变更后需同步数值断言。

## 3. 功能验收用例

### G｜流程与资源

| ID | 操作或前提 | 预期 |
|---|---|---|
| G01 | 新建游戏 | 日1准备；钱包50、累计产能0；4员工；仅N01/N02开放；仅制式装备 |
| G02 | N01观察正常完成 | 24秒实际作业后，钱包和累计产能各+12；未完成时不分段付钱 |
| G03 | 累计产能150、钱包80，施放消耗16的恢复 | 钱包64；累计产能150；结束当天仍可用 |
| G04 | 钱包不足时购买/施法 | 无负数钱包，无半解锁状态，清楚提示失败 |
| G05 | 累计达标但N01仍失效 | 可确认结束当天；记录事故；不要求镇压后才能退出 |
| G06 | 累计未达标，但钱包因跨日结余高于目标 | 不能结束；日目标读取累计产能而非钱包 |
| G07 | 结算时有进行中和在路上的工作 | 全部取消，均无额外产能；没有晚到动画回调加钱 |
| G08 | 进入次日 | 钱包/解锁/装备保留；产能归零；HP/SP恢复；压力与冷却重置；按日配置加1人并开放房间 |
| G09 | 正常镇压主样本或击败分身 | 产能、钱包均不因击杀增加 |
| G10 | 首次经费、日结算或重读存档 | 首次经费只发一次；没有每天再发50或重复结算奖励 |
| G11 | 全员惊慌 vs 全员重伤 | 惊慌者能撤退恢复，不判失败；全员重伤触发本日失败 |
| G12 | 第三日达标结算 | 进入完成页，不自动生成第四日 |

### W｜工作、压力和优先级

| ID | 操作或前提 | 预期 |
|---|---|---|
| W01 | 给远处员工下工作命令 | 先预约并走路；到工作位才计作业时长 |
| W02 | 第二名员工预约忙碌房间 | 被拒绝，不会形成隐藏等待队列 |
| W03 | 主动取消进行一半的工作 | 0能量、0额外压力；释放房间与员工关联 |
| W04 | 房间压力90，完成基础+25的互动 | 触发失效，本次0能量；不能先收入再失效 |
| W05 | 失效和10秒恢复期间尝试工作 | 拒绝；长期推进也无产能；恢复完压力25才能再次预约 |
| W06 | N04广播命中与某工作到期位于同一步 | 中断优先，该工作0能量；房间紧急中断压力只加一次8 |
| W07 | N04因工作到期失效并使N03压力过线；N03工作也同时到期 | 所有压力/联动先处理，N03这次不得因遍历顺序而入账 |
| W08 | 完成时工作损伤使员工SP归零或HP归零 | 该工作紧急失败，0收入；仍收容房间仅结算一次紧急中断+8，不再加正常工作压力 |
| W09 | 非N05房间长期空闲 | 除N02的记录清理外，不自动涨压力或触发隐藏惩罚 |
| W10 | 稳定工作成功后员工到门口 | 员工待命，不自动开始下一次工作 |
| W11 | N01连续两次互动 | 第二次基础+25外再+15；观察/安抚完成后下次互动不加连续罚值 |
| W12 | N02相同员工连续完成两次工作 | 第二次额外+15；换员工不加；空闲满20秒清除旧员工记录 |
| W13 | N03距离上次完成7秒时真正开工 vs 8秒时开工 | 前者完成额外+10，后者不加；下令时间不是开工时间 |
| W14 | N04完成三次非安抚，再安抚 | 第三次额外+20并归零；安抚独立清空计数 |
| W15 | N05空闲30秒后再空闲5秒 | 压力额外+5；实际作业期间计时冻结 |
| W16 | N05反复开始并立即取消工作 | 不把空闲计时清零；成功完成一次才清零 |
| W17 | 房间未开放或恢复中推进空闲时间 | N05不会偷偷累积空闲压力；开放/恢复开始时计时为0 |

### C｜战斗、员工与装备

| ID | 操作或前提 | 预期 |
|---|---|---|
| C01 | HP/SP均100，红伤12、红倍率0.6 | HP92.8、SP100 |
| C02 | HP/SP均100，白伤12、白倍率0.6 | HP100、SP92.8 |
| C03 | HP/SP均100，黑伤12、黑倍率0.6 | HP/SP均92.8；不能各减3.6，也不能重复判伤 |
| C04 | 最大HP100，苍白6%、倍率0.55，当前HP50 | 减3.3，剩46.7；基数仍是100，不是当前50 |
| C05 | 敌人最大镇压240，苍白倍率1.2，受4%苍白 | 镇压值减11.52；连续攻击不按剩余值递减 |
| C06 | 单条镇压值敌人受黑伤9、倍率0.7 | 仅减6.3一次，不扣两份 |
| C07 | 给员工换不同护甲再次遭受同种伤害 | 结果确实随承伤倍率改变；不能只有图标变了 |
| C08 | 尝试同一专属武器给两个人同时穿戴 | 最多一个持有；安全转移可行；前持有人回制式装备或库存逻辑正确 |
| C09 | 当前/原持有人在走廊作战时换装 | 拒绝，不能瞬间转移抗性规避攻击 |
| C10 | 玩家下撤退命令 | 取消未命中前摇和追击，沿路去安全室；不自动回头打敌人 |
| C11 | 敌目标消失，镇压命令结束 | 待命，不自行锁定另一个目标 |
| C12 | 奶龙失效一次 | 一主两分身，永不超过两只分身，不递归复制 |
| C13 | 镇压奶龙主样本 | 同一次失效的分身立即清除；主房间恢复10秒；无能量掉落 |
| C14 | 大狗/咕咕嘎嘎已前摇，员工在命中前离开圆形范围 | 不受该次伤害；不是蓄力开始就锁定必中 |
| C15 | 敌方广播作用于安全室内员工与支路上的员工 | 前者免疫；后者未抵达安全室，仍可受广播伤害 |
| C16 | 员工SP0 | 惊慌撤退，不伤同事；SP达到35恢复控制；HP同时0优先重伤 |
| C17 | 员工在安全室停3秒后再待2秒 | HP增加10、SP增加16（均不超过最大）；离开重进需重新等待3秒 |
| C18 | 重伤与次日恢复 | 本日无法操作，不掉装备；次日完整恢复，可继续工作 |

## 4. 手工试玩观察，不得伪装成自动证明

以下是需要实际招人试玩后回答的问题，而非只看测试绿灯：首次事故后玩家能否说出原因；技能是否只是省损失而非必选钥匙；玩家是否看得懂“黑伤各扣HP/SP”和“承伤倍率越低越好”；是否因为等待或重复点选而感到拖沓；五物联动是否只是突然一起爆炸，还是能通过优先处理源头改变结果。

第一轮记录总时长、每物失效次数、每次技能使用、重伤人数、重试次数、日结算时钱包、档案/装备/技能购买顺序。只输出本地日志，不接入在线分析服务。

调整优先级：先修状态错误与信息不可读，再改技能/伤害数值，再改产能与节奏，最后再考虑追加内容。不能用“再加一个系统”掩盖基础循环不好玩。

## 5. 最终交付格式

README写真实启动/构建/测试命令；STATUS列实际完成的M阶段；测试报告逐条标记通过、失败或未执行；至少给正常作业、两物联动、装备/技能、日结算四种真实截图，并按V12提供连续操作记录，展示途中改令、进室作业与失效镇压。截图由真实游戏产生，不用概念图替代。

没有运行环境时，可以交付未运行代码与执行步骤，但必须明确“未运行”；不把设计包里的公式测试当成游戏实现测试。
