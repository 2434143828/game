# v0.5 基地样板组件规范与验收边界

日期：2026-10-25。范围仅 N01 奶龙收容室、SAFE 医疗休憩区、`N01 门侧 → a-top` 连接走廊及 SAFE 入口接缝。本文为可复用美术契约，不授权替换其他房间，也不代表运行验收已经通过。实际结果以本轮证据目录和操作记录为准。

## 为什么之前的样板仍不统一

正式环境由 `src/scenes/facility/architecture.ts` 的 `drawGeneratedArchitecture()` 调用 `EnvironmentArt` 画入环境容器；有完整环境纹理时，不使用上方的程序绘制 fallback。只修改 fallback 或 CSS 无法解决正式画面的资产风格。

| 原资源或实现 | 具体问题 | 样板处理原则 |
| --- | --- | --- |
| `public/art/nm-v2/environment/nm_v2_env_wall_cladding_upper_neutral.png`、`nm_v2_env_wall_cladding_upper_clinical.png` | 墙面与角色的简化形状、有限明暗不一致 | 样板使用大色块墙体，保留功能分区，不沿用复杂金属板材 |
| `nm_v2_env_room_shell_*`、`nm_v2_env_floor_segment_*` | 厚机械边框与密集地板细节在小镜头中形成强亮暗边缘 | 样板边框和地面一起统一，不能只更换框内插画 |
| `nm_v2_env_access_door_frame_frame.png`、`nm_v2_env_access_door_leaf_leaf.png` | 旧门留在新墙上会成为明显异质接口 | 保留门状态绑定，替换门框与门叶视觉；不在背景里再烘焙一扇假功能门 |
| `nm_v2_env_linear_ceiling_light_*`、`nm_v2_env_service_conduit_*` | 灯、管线的材质和机械细节与柔和手绘室内冲突 | 使用简洁灯具和单层线槽，只保留读图必要部分 |
| `nm_v2_env_recovery_couch_*`、`nm_v2_env_medical_station_*`、`nm_v2_env_touch_console_console.png` | 独立写实设备与 Q 版人物缺乏统一尺寸及描边 | 设备按角色身高建立比例；医疗用床、药柜识别，工作用终端识别 |
| 室内样板图盖在旧壳体、旧设备之上 | 原边框、旧地板、门及医疗区旧灯仍露出，叠图不等于完整样板 | 样板范围内由同一套墙、地、道具、门体系接管；范围外继续旧资源 |
| `EnvironmentArt.draw()` / `drawSlice()` 直接 `setDisplaySize()` | 任意比例缩放会改变线宽和设备比例 | 先裁去源图底部地板，按人物比例确定家具高度，再补齐静态墙面；医疗图等比缩放，N01 与走廊使用已记录的显示尺寸 |
| 原走廊图摆在 `(900,342)`、显示为 `500×282` | 真实脚线 `y=460` 落在画面高度约 42% 处，图片底部到 `y=624`；图中地板若靠下就与真实行走层冲突 | 真实脚线是唯一地面基准；不得为了图片移动寻路或角色 |

旧 alias 名称带 `industrial` 并不单独证明材质风格；真正加载路径由 `src/art/generated/nm-v2-environment-map.json` 映射确定。以上列的是实际映射资源和布局原因。

## 单位、尺度与画面层级

所有以下尺寸均为 **world px、镜头缩放前**。员工基准来自 `src/scenes/facility/geometry.ts` 的 `employeeHeight = 66`；角色仍使用现有 `HumanRig` / `CreatureRig`。不要为适配环境图改变人物或收容物实体比例。

| 项目 | 样板规则 |
| --- | --- |
| 外轮廓 | 样板结构深灰墨线 `#303D3B`，2–2.5 world px；图内手绘线条保持低对比，不增加第二圈厚框 |
| 内部分割 | 1–1.5 world px，颜色比外轮廓浅；避免细小划痕和重复铆钉 |
| 明暗 | 底色 + 一层阴影 + 可选局部亮面，共 2–3 档；阴影为整块形状，禁止连续金属高光 |
| 纸感 | 只允许低对比底色变化；缩到默认镜头后不应可见密集噪点 |
| 视觉顺序 | 活动角色/异常与状态反馈 → 可操作设施、门 → 识别性设备 → 大块墙面 → 远景 |
| 留白 | 角色活动带后方至少一半面积为连续低细节色块；不把密集线条放在人脸和武器后面 |
| 基色建议 | 墙面暖白 `#E8DFD2` / `#EBE2CF`、浅鼠尾草 `#A5AB9A`、框条 `#9EA998`、地面灰绿 `#BCC4AF`、底部单层阴影 `#7C8B80`；这是一套样板色板，不对旧场景做全局滤镜 |
| 功能色 | N01 使用少量柔黄，SAFE 使用低饱和绿；高饱和警告色留给真实危险反馈 |

`config/facility.json` 默认 zoom 为 0.6，员工高度约 40 screen px。必须同时检查默认缩放和房间聚焦；仅在大图或最大缩放好看不算过关。总览可以用于空间方向检查，不能代替道具比例验收。

## 可复用组件契约

| 组件 | 比例、锚点和形状 | 功能及禁用项 |
| --- | --- | --- |
| 墙 | 上墙占大块面积，下墙/护墙带高 42–58；每 180–240 横向距离最多一条结构接缝 | 保留现代机构感；禁止蜂窝金属、复杂外露管网、军事装甲板 |
| 地板 | 承重接触带以导航脚线 `F` 为准，15 px 承重面与 9 px 单层阴影均放在 `F` 以下；接缝间距 130 | 站立脚不能悬浮在第二条地板上；横向接缝不可伪装成台阶 |
| 门 | 保持既有门节点和124 高的侧剖面开口，门叶高 122，顶框距脚线 127、宽 38；圆角/浅倒角用统一墨线 | 门叶独立对象，开关来自 `setDoorOpen`；背景里不出现额外可误认的路径入口 |
| 灯 | 灯体宽 70–140、高 10–17；每一区域 1–2 个清楚光源 | 柔和有限光块；不做全屏滤镜，不用耀斑或反射抢人物 |
| 观察窗 | 简单粗外框和一块雾蓝玻璃，最多一条低对比反光 | 不能像高光金属舱门；不遮挡奶龙身体轮廓 |
| 终端 | 台面高度约 35–60，屏幕不高于人物头部太多；宽约 55–85 | 奶龙工作位附近有明确朝向的终端；静态屏幕不得伪装实时数值 |
| 医疗床 | 本轮样板床长约 165、床垫高约 32–46、靠背最高约 69；一张床约 2.5 个员工身高长 | 枕头、床垫、药柜建立医疗识别；不用机械手、军用手术舱 |
| 药柜 | 本轮柜体宽约 61、高约 92；两个大柜格、一处医疗标识 | 图标优先，不烘焙长说明文字；不得暗示新增可操作系统 |
| 走廊 | 样板墙从 `x=810` 到 `x=1400`，覆盖门侧连接段，地面 `y=460`、墙高 170；SAFE 入口补齐 `x=1400→1650, y=1130` | 交接到联络井时不能遮住真实出口；不添加不存在的楼梯或绕行路 |
| 装饰 | 每处最多 2–3 个低对比元素；普通饰物不高于员工身体 | 用告示牌/植物/软垫帮助定位；禁止为了精美堆管线、货箱、花纹 |

完整背景可作为本次样板的静态墙面/道具层，但动态门、角色和状态不得烘焙进去。后续拆模块时沿用以上尺度和色板，不要求本轮为三个区域创建全基地模块库。

## 当前素材与落地尺寸

新素材位于 `public/art/facility-v05-slice/`，由 `FacilitySliceArt.ts` 接管样板的墙、框、地板和门。旧工业壳体、室内设备、灯和桥面在这三个区域不再绘制；其他区域保持原样。`facilityArt=legacy` 仅在 DEV 生效，用于真实旧版环境的同镜头对照。缺失任一新纹理时，三个区域完整回退旧版，不留下空白房间。

## 必须补齐的运行证据

本轮最终对照和操作证据已整理到 [实际验收记录](FACILITY_V05_ACCEPTANCE.md)。下述文字保留为早期审查发现与验收清单，最终结果以该记录为准。

本次静态审查时，旧证据目录只有一张历史总览 `before-baseline-2026-10-20.png`；医疗区与走廊的 `after` 也是总览，不能独立证明三个样板通过。应保留历史证据并增加以下内容：

1. N01、SAFE、连接走廊各一组同画幅、同镜头、同状态的实际运行前后图。临时只切换环境视觉作为对照可以，必须明确标注，不修改存档或模拟数据。
2. 一张完整整合实机图，保留现有员工和奶龙，展示样板与未改区域边界。
3. 一次连续操作记录：员工沿走廊移动与改令 → 进 N01 工作 → 去 SAFE；观察脚线、门、角色遮挡与状态。操作结果由运行现场记录，不以静态图推断。
4. 一次暂停检查：暂停时角色不移动，环境替换不会产生独立假动作；恢复后继续原有状态驱动动作。
5. 类型、测试、构建结果与运行检查分别列出。数值测试通过不等于视觉通过。

## 扩展前的判断

三个样板同时满足描边、有限明暗、人物比例、脚线对齐、门状态和视觉重心，才具备向其他房间复用的条件。本轮不修改 N02–N05，不改地图/寻路/战斗/E.G.O./存档逻辑。需要用户判断的是这套样板是否属于同一个 2D 游戏世界；不能把自动测试或美术精度当作用户风格认可。
