# 《网梗收容：奶龙失效》美术风格一致性优化补丁 v0.5

> 类型：现有 Phaser 2D / TypeScript 项目的**增量美术与界面改造规格**  
> 基线：`GAMEPLAY_FLOW_BOOK_V03.md`（2026-10-24）及项目后续已合并的玩法补丁；实际工程内容高于文档中的假设。  
> 配套：`CODEX_执行任务.md`、`reference_screenshots/01_facility_current.png`、`02_archive_current.png`、`03_combat_current.png`。  
> 目标：**减轻风格拼贴与模板化 UI 的观感，形成“克制的现代收容机构 × 手绘模因异常”的独特视觉语言。**

## 0. 工作范围和绝对约束

### 0.1 本次只改表现，不重做玩法

- **保留**真实 2D 设施剖面、走廊路径、角色移动、摄像机、房间实体；主动失效、外勤抓捕、三人自动普攻、E.G.O. 卡牌干预、战术暂停及抽牌/冷却、养成、存档、战斗结算的现有业务规则。
- **保留** N01 奶龙、N02 耄耋、N03 大狗、N04 叮咚鸡、N05 咕咕嘎嘎，以及已投入的自有角色与收容物图像资源。不得把整套设施替换为静态背景、文字游戏或无角色移动的卡片页。
- **不新增**卡牌技能、数值机制、资源、人物设定，不修改当前已配置的卡牌名字、效果、E.G.O. 装备与阶级数据。文中出现的文字/示例色值均为视觉示例，不是改动数值配置的授权。
- **不要无差别调用生图，生成 15–18 张互不统一的华丽插图。** 优先从当前资产与代码可组合的图形、裁切、覆盖层、统一模板实现。资源缺失列入待补资产清单，不要用不明来源的第三方游戏截图直接做商用资产。
- 旧经典三日入口与存档结构不应受影响。改造 UI 时保留鼠标、键盘、暂停、目标选择、拖线施牌、移动、回到设施等功能。

### 0.2 视觉改造的核心判据

现在的问题不是精细度低，而是每个层级来自不同的“游戏”：写实灰白设施、Q 版员工、手绘奶龙、冷蓝后台式面板、华丽二游卡图。**本次要消除的是语言不一致，而非一味增加特效和内容。**

确定的新方向：

> **正常时：一所认真经营的现代新媒体异常收容研究机构。** 视觉克制、好读、像有真实制度的机构。  
> **收容失效/出牌时：互联网模因越过屏幕边界，局部污染现场。** 荒诞、复读、弹幕、伪通知、图像复制与错位；但绝不遮蔽目标、员工与战斗状态。

不要误做成：传统重工业末日地堡、全屏霓虹赛博朋克、纯“科研蓝色后台”、抽象恐怖血污、泛二游大立绘卡牌、全程持续故障闪烁。

## 2. 统一美术圣经（Art Bible）

### 2.1 形状、材质、绘制语言

| 元素 | 统一规范 | 禁止 |
|---|---|---|
| 设施建筑 | 现代可辨识的实验/办公空间；低到中等纹理密度，色面和少量线条表现结构 | 每块墙板都堆机械划痕、螺丝与噪点 |
| 2D 角色 | 参考现有奶龙手绘形象的**柔和实体轮廓**；保证与员工在同一渲染世界中有相近的描边和影调 | 员工像高清二游立绘缩小、怪物像单独贴纸 |
| 光影 | 主要材质 2–3 个明度层级 + 少量定向高光；环境弱、角色与目标强 | 同屏同时出现 PBR 写实高光、厚涂立绘和像素图 |
| 线条 | UI 结构线约 1–2 CSS px；世界物件轮廓按世界坐标等效缩放；同类资源统一线粗 | 不同图片混用无描边、黑粗线、3D 边线 |
| 纹理 | 局部低对比纸感/扫描噪声用于档案和异常信息，不覆盖主要数值与文字 | 全屏彩噪、全屏色差、无意义网格背景 |
| 交互 | 反馈来自选中轮廓、聚焦、位移、少量特效；关键按钮有显著区别 | 所有按钮都同一种蓝色发光描边 |

  --wg-meme-pink: #F36CA6;  /* 失效污染专用 */
  --wg-meme-violet: #A68BED;

### 2.3 字体层级

- 简体中文正文优先当前工程可用字体（系统回退即可），英文和编号可以等宽字作辅助；不引入授权不明字体文件。
- 仅保留 3 层：`标题`、`核心数据/按钮`、`辅助说明`。字号推荐桌面基线：标题 18–24px，核心正文 13–16px，辅助文字至少 12px；1280×720 下能读清关键数字。不要把关键效果文案缩到 10px。
- `N01 / E.G.O. / LIVE / LOCKED` 是氛围标识，不是主要内容。中文操作标题、等级、产能优先。统一术语采用工程现有名称，别把已有 `N01` 强制改成另一个编号体系。

## 3. 设施主界面（P1）

### 3.1 视觉层级

从高到低：**当前选择的收容物/员工 > 可交互目标与行动反馈 > 设施功能房间 > 结构与景深背景 > 纯装饰**。

- 保留设施剖面结构与通行路径；只降低远景背景的纹理对比，不缩减实际可交互空间。
- 默认总览显示设施全貌，选中房间时以现有镜头系统**平滑聚焦**；不自动大幅摇镜造成方向感丢失。相机动画约 180–320ms，尊重用户主动缩放与视角控制。
- 员工、收容物以**描边清晰、底部接触阴影、清楚的选中圈**突显；不要统一把精灵强行放大到导致门宽/寻路碰撞失真。优先做局部对比、相机聚焦与状态标记。
- 非选中收容室可保留编号、锁定图标；远景不显示密集长文字。选中后再出现名称、阶级、产能和行动入口。

### 3.2 HUD 精简（不删除功能）

- 顶部一行只强调：当前状态（设施/战斗）、总能量、总产能、暂停/倍速；次要时间、版本信息放低优先级。
- 右侧员工列表默认紧凑展示头像、HP/SP、行动状态；选中员工后展开详细说明，避免所有信息块大小相同。
- 底部五个收容物卡片改为**可收起的收容目录条**：图标/名称/阶级/是否可挑战（最多一行）；目前锁定状态用清晰图标区分。保持可点击与房间联动；目录不得挤压设施镜头。只有打开详细信息时显示长描述。
- “下一目标”保留并与收容目录联动，默认占用一个小区域，不再嵌套三重卡框；满足条件时强化主 CTA（主操作按钮）。
- 不要把所有面板都做成统一的 `border: 1px solid #5ca...`。优先依赖留白、字号和对齐，分割线仅在需要时出现。

### 3.3 状态与声音（可选）

- 正常态：低对比环境信息，设备轻微指示灯，角色待机动作。
- 进入主动失效：当前房间/战斗区域出现**局部警示与专属模因污染**，不将整个 UI 染成紫红，也不遮挡员工与敌人血条。
- 战斗结束：淡出污染、房间重新稳定，产能恢复的反馈在顶部或对应房间出现一次，不持续跳动。
- 音效仅建议短促的设备确认声与各异常专属轻提示；若缺素材可留接口，不把本轮作为阻断项。

## 4. 收容档案（P1）

**保留目前“左侧身份牌 + 右侧内容”的框架和档案入口，重排层级，绝不再变成大块营销弹窗。**

建议结构：

```text
┌─────────────────────────────────────────────────────────────────────┐
│ N01 · 收容档案 / CONTAINMENT FILE                  [状态]  [×关闭] │
├─────────────────────┬───────────────────────────────────────────────┤
│ 手绘收容物插画       │ 奶龙 / 当前阶级 I / 当前产能 2E/分钟          │
│ ID N01              │ ───────────────────────────────────────────── │
│ 已收容 / 风险标识    │ 01 观察记录：简短关键行为描述                 │
│ 档案编号、修订时间  │ 02 失效须知：主样本 + 两名复制分身           │
│                     │ 03 E.G.O.：武器/防具等级与三张卡识别         │
│ [收容状态与小数值]  │ 04 升阶进度/下一阶奖励（读当前数据）           │
│                     │ [小尺寸批注/研究戳记，可选]                 │
└─────────────────────┴───────────────────────────────────────────────┘
```

- 左侧现有奶龙插画**优先复用**，不要为追求统一将它改成冷蓝 3D 肖像。其柔和、稍带不安的手绘感是角色风格参考。
- 右侧不再平分四块同面积数据盒。**行为与失效须知占最大阅读面积**，装备与产能是结构化次级区域；空余留白经过排版处理，不能靠增加无意义“模块”填满。
- 记录编号、机构印记、小型红色批注、删节线只放在档案内容边缘，且仅用项目自身可复用素材/文本；**不要伪造大量高密度难以阅读的随机英文科学文字**。
- 已收容/未收容两种状态都要能读；未收容不提前显示玩家不应知晓的完整异常细节（遵守项目当前解锁权限）。
- 不要覆写当前实装档案说明；新增研究叙事文字必须是经策划确认的真实文案，先用项目当前已有文案。

## 5. E.G.O. 卡牌与战斗 HUD（P0，最高优先级）

### 5.1 根本改造目标

`03_combat_current.png` 里出现的默认卡为《制式训练》来源、例如“紧急截断”“简易格挡”，其插图大量使用蓝白高光的战术人物绘画，明显与场景内的小比例手绘员工及奶龙不一致。

**优先建立一套“机构批准的 E.G.O. 战术模块卡”统一框架。** 风格关键词：扁平形状 + 手绘动作剪影 + 少量机构标识 + E.G.O. 专属污染纹理。不是高细节人物立绘的缩略版。

当前已有制式训练等非五收容物卡，**这些也要纳入统一模板**，不得只统一 N01–N05，留下默认三张卡独立画风。

### 5.2 卡牌信息架构（小卡与放大预览）

```text
┌─────────────────────┐
│ N01   [复制/特殊图标]│ ← 来源+类型，固定位置
├─────────────────────┤
│                     │
│    简洁的动作剪影    │ ← 中区 50–55%，同画法
│   （复制残影×2）    │
│                     │
├─────────────────────┤
│ 复制粘贴             │ ← 中文卡名，优先
│ 复制上一效果…        │ ← 只显示1–2行缩略，详述悬停/长按
│ A-01      I 阶      │ ← 卡所属员工+阶级
└─────────────────────┘
```

- 卡片尺寸推荐在 1280×720 的战斗场景基线下：正常约 **112–132px 宽 / 162–188px 高**，保持约 0.70 的宽高比；根据可用宽度动态缩放，禁止固定到 2048 截图分辨率。
- 卡牌来源（N01/N02/STD）、类型（攻击/防御/控制/辅助）、所属员工、名字、当前可用性必须读得清。
- 详细效果不要求塞进缩略卡；通过悬停/长按放大预览，显示完整技能说明及来源 E.G.O.。
- 主插图与文字独立图层；一张卡图资源更换不应该要求重新绘制整张带文字的图片。
- 卡牌框通用结构共用一套 DOM/SVG/Canvas 模板（以项目现有渲染方式为准），颜色和主图数据驱动；**不要为 18 张卡复制 18 套 UI 代码**。

### 5.3 卡面生成的保底实现（无需新增图片即可先执行）

卡面的主视觉不允许继续“放一张随机 AI 二游人物插图”。按以下优先级选：

1. **第一优先：** 已有收容物手绘立绘裁切 + 统一二维图形化技能动作（复制分身、拳击冲击、音波、通知、泡泡）。
2. **第二优先：** 在 Phaser/Canvas/SVG 里用可复用的矢量剪影和图案组合绘制技能画面；每张卡使用同一种阴影/描边/色块体系。
3. **第三优先：** 图像资产不够就使用精心排版的机制图示作为占位，明确标记为待替换美术，而不是临时抓不明来源图片。

统一三层：底色纹理（低对比）→ 主体动作形状（高对比）→ 1 个来源符号。小图最大限度保留大轮廓，不做密集小字。

### 5.4 五种来源的 3 卡视觉母题

| 来源 | 三张技能图的统一作画约束 | 差异构图 |
|---|---|---|
| N01 奶龙 | 奶黄底 + 圆形留白 + 双影 | 单体前冲 / 双重轮廓 / 多层叠像 |
| N02 耄耋 | 赭红底 + 斜向爆裂线 + 断裂框 | 近身冲击 / 反击折线 / 情绪升温锯齿 |
| N03 大狗 | 珊瑚橙底 + 同心音波 + 直播热度小标识 | 扇面声波 / 破防撞击 / 波峰放大 |
| N04 叮咚鸡 | 提醒黄底 + 播报条 + 系统提示框 | 单次通知 / 回环广播 / 扩音波形 |
| N05 咕咕嘎嘎 | 浅紫底 + 泡泡 + 柔波线 | 单体安抚 / 罩状护盾 / 群体共振 |

每组卡应通过**同一组色彩、造型和符号**判断来源，三张卡之间通过动作图形判断作用。具体卡名和技能含义以工程数据为准；不得根据上表擅改游戏数值或把卡牌效果改成另一种机制。

### 5.5 卡牌状态和动效（必须落地）

| 状态 | 视觉变化 | 推荐时长 | 说明 |
|---|---|---|---|
| 待机 | 低幅度呼吸感或静止，边框克制 | 1.8–2.4s 周期 | 最好默认接近静态，避免全体晃动 |
| 可使用 | 主体全彩 + 清晰来源色边框 | 即时 | 与禁用可区分 |
| 悬停/长按 | 上浮约 8–14px、放大 1.08–1.12 倍 | 120–160ms | 不能遮挡敌方关键意图 |
| 选中 | 轮廓强化、员工关联高亮、合法目标描边 | 100–160ms | 鼠标目标箭头沿用现有逻辑 |
| 预备 | 主角标记“待执行”，进入原有出牌队列 | 即时 | 暂停时可预备，不先结算伤害 |
| 施放 | 从手牌上浮→朝所属员工/目标投出数据模块→短爆散→员工动作生效 | 180–300ms 的 UI 动画 | **不得使模拟逻辑提前伤害或延后判定**；真实移动与前摇优先 |
| 公共冷却 | 卡面灰化，灰色区域**从上到下退去**，底部最后恢复彩色 | 以实际 2.5 模拟秒为准 | 实际时间由引擎数据驱动，不另启 wall-clock 计时器 |
| 冷却结束 | 全彩 + 低幅度扫光 | 100–180ms | 不叠加闪屏 |
| 无合法目标 | 暗化而非冷却灰化 + 简短原因 | 即时 | 与冷却区别明显 |
| 弃牌/抽牌 | 短位移与缓动，牌库和弃牌数同步 | 160–250ms | 不阻塞输入或抽牌业务 |

**“灰色从上往下解冻”数学定义：** 令 `p = clamp(1 - cooldownRemaining / cooldownDuration, 0, 1)`。冷却刚开始 `p=0`，整牌灰化；冷却过半 `p=0.5`，上半恢复原彩、下半灰；冷却结束 `p=1`，整牌原彩。可用 CSS mask/clip-path/Canvas 裁切实现；注意需要表现为 **灰色遮罩从顶部开始消失，灰层下沿向下移动**，不要做成由底部向上充色。

**非常重要：** 当前 2.5 秒是**所有手牌共享出牌冷却**，不是“每张用过的牌重新回到手里等冷却”。被打出的卡依原逻辑进入弃牌堆；公共冷却期间灰化当前手牌及公共冷却指示器，不能在弃牌后凭空保留一张“已用牌”作为冷却占位。若当前项目视觉已实现灰层，则沿用并修正方向/对比，而不是重写数据逻辑。

### 5.6 来源角色联动

- 卡牌显示 `A-01 / A-02 / A-03` 所属员工（以当前真实持卡人 ID 为准）。
- 选中后，场上持卡员工脚底描边闪一次；已有 `ENEMY/ALLY` 指向箭头沿用真实合法目标与吸附规则。
- 施放后由**实际所属员工**发起技能动画，命中效果放到实际命中目标，卡飞行只是辅助演出。
- 离场、死亡、暂停、技能前摇被打断时不能产生卡面与业务状态错位。

## 6. 战斗画面/HUD 布局（P0）

### 6.1 推荐比例（以 1280×720 为基线，不写死像素）

- **战场：** 高度约占主体可用空间 65–72%；员工、敌人、预告和目标箭头始终完整可读。
- **下方牌区：** 高度约 22–28%；三张首发卡居中或左中，右侧放极简牌库/弃牌/当前公共冷却。当前截图下方大片空白必须通过布局与背景承接改善，而不是盲目放大卡到挡住角色。
- **右侧侧栏：** 战斗时默认紧凑显示 3 名员工 HP/SP、当前敌人意图；非战斗行动列表折叠或淡化。
- **顶部：** 能量/产能/倍速/暂停统一收敛。重复状态信息不要出现两三次。

**不能**简单用固定百分比改变 Phaser Canvas 的摄像机/世界坐标。依据现有 DOM 与 Phaser 容器结构，逐步调整面板尺寸与 canvas 可视区域，保证世界点击位置、目标箭头及特效坐标准确。

### 6.2 可读性和响应式

- 桌面测试：`2048×1169`（当前参考截图近似）、`1600×900`、`1280×720`。实际 Chrome 还应按设备像素比验证，截图尺寸不一定等于 CSS viewport。
- `1280×720` 卡名、员工 HP/SP、敌方蓄力意图必须读得清；4 张手牌同时出现不重叠关键字。
- `<= 1024px` 做紧凑牌区/可滚动列表，但不得因此禁止鼠标/触屏选牌；若移动端尚未实装，在报告中如实标记为未覆盖。
- 模态弹窗层级必须高于战斗并保持暂停冻结，关闭后不擅自恢复模拟（保留 v0.3 行为）。

## 7. 模因污染的节制演出（P1/P2）

原则：**异常是打破机构秩序的局部事件，而不是全屏滤镜。**

| 场景 | 最小可用视觉表现 | 可选增强 |
|---|---|---|
| N01 主动失效 | 出现两份复制残影/重复的小型对话框，随主样本和分身真实位置生成 | 房间编号短暂重复、复制扫描线 |
| N02 外勤 | 对应现实外勤背景的口角/表情包式短促爆点 | 社区公告牌出现异常文字 |
| N03 外勤 | 独立声波圆环、热度值外溢 | 广场屏幕模拟直播走红 |
| N04 外勤 | 听觉可视化波形、系统播报条 | 地铁/取餐屏幕被重复通知覆盖 |
| N05 外勤 | 柔波/小型情绪共鸣圈 | 本应安抚的提示音局部重复 |

- 上表是视觉演出方向，不据此擅改技能伤害/战斗规则。**外勤必须显示各自的现实场景，而非统一实验室换色。**已有外勤五图的进入、加载与实际作战，需单独验证。
- 特效只出现在对应事件或技能触发的 **250–900ms** 窗口；不持续高频闪烁，污染层不应覆盖可交互的敌人、员工、血条、技能命中点。
- 添加 reduced-motion（减少动态效果）模式时保留必要的选中/冷却反馈，减少亮光和晃动，不减少游戏功能。

## 8. 资源生产与程序实现要求

### 8.1 资源目录（示例，需尊重现有项目结构）

```text
assets/
  ui/
    tokens/                  # 色彩、字号、边框、阴影
    cards/
      card_frame.*           # 一套结构，多 E.G.O. 主题
      card_symbols.*         # 攻击/防御/控制/辅助 + 来源标识
      source_n01.*           # 小幅来源特征图/纹理
      source_n02.*
      ...
    archive/                  # 档案扫描线、标签、印记，轻量可复用
    effects/                  # 复制/音波/广播/泡泡等表现
```

这是逻辑分类，不要求 Codex 机械新建无意义目录。项目已存在可复用资产应就地整理，并保留旧路径别名或迁移脚本，避免断链。

### 8.2 风格一致性检查工具

- 制作一个仅在开发环境打开的 `visual-review` **预览/测试入口（可选）**，一次展示：标准卡、五来源卡、普通/选中/公共冷却 0/50/100%、不可用、4 张手牌、档案已收容/未收容，方便截图审查。
- 如果预览页会干扰现有路由，不要强行新增入口。直接使用真实游戏截图作基准即可。
- 对重绘或调整过的资产建立表：`旧路径 → 新路径 → 场景 → 状态（复用/重绘/待补）`。
- 不依赖外网动态加载关键美术；后期素材替换只改资产映射，不改业务事件。

### 8.3 保留的技术约束

- 维持 Phaser 2D 固定步模拟、现有实体与寻路事件，视觉动画不得修改帧同步或决定胜负结算。
- 冷却填充读取现有**模拟秒**剩余时间；暂停、1×、2×时必须同步；不能依靠 CSS 独立计时导致“游戏暂停卡还在解冻”。
- 用户输入先触发既有卡牌合法性/目标选择逻辑，视觉只订阅状态，不制造第二份卡组或冷却状态。
- 新视觉效果要能释放资源，重复进出设施、外勤、档案不会累计监听器或泄漏纹理。

## 10. 验收标准（失败即需返工或明确记录）

### A. 静态视觉

- [ ] 设施、员工、收容物、卡面不再出现明显三套绘制风格（描边、光影、材质需一致）。
- [ ] 统一卡模板覆盖制式训练与 N01–N05 所有**实际已实现** E.G.O. 卡，而不只换三张样图。
- [ ] 1280×720 下主战场优先、4 张手牌无信息重叠、文本可读。
- [ ] 收容档案左栏头像/编号、右栏记录/须知/装备/产能层级清晰；未收容态不泄漏隐藏信息。
- [ ] 5 类来源色与符号能区分；不只依赖颜色识别。

### B. 交互与动效

- [ ] 点击卡→预选→目标指引→真实员工移动/前摇→命中结算→弃牌，流程完整。
- [ ] 冷却进度 0%、50%、100% 各截图；**上半先恢复颜色、下半后恢复**。
- [ ] 暂停时灰层冻结；1×/2×与模拟时钟同步；技能不可用与公共冷却明显区分。
- [ ] 现有 `ENEMY/ALLY/SELF/TEAM` 选牌和鼠标箭头规则无回归。
- [ ] 角色/目标位移不破坏卡牌箭头吸附和命中点坐标，退出战斗后不残留手牌/特效。

### C. 流程与稳定性

- [ ] 默认 `/` 仍进入设施；奶龙主动挑战 I→II；外勤 N02 捕获成功/失败均正常回设施。
- [ ] 关闭/刷新处理、离线收益、存档兼容保持原有行为；旧 `?mode=campaign` 可启动（如果工程仍有该入口）。
- [ ] `npm run test`、`npm run typecheck`、`npm run build` 运行并报告真实结果；存在时再执行 Python 验证脚本，不虚报测试覆盖。
- [ ] 逐步截图对比（同场景、同相机、同画布尺寸），并在报告中列出改动文件、资源表和遗留问题。

## 11. 明确禁止的“伪完成”

1. 全局改 CSS 主色、把按钮圆角变大，就声称完成美术统一。
2. 保留高度割裂的二游卡面，只加一个同色边框。
3. 把科技风复杂化成更多英文标签、随机二维码、假参数、全屏故障滤镜。
4. 把 2D 设施改成静态背景截图，破坏房间、走廊、员工移动和真实战斗交互。
5. 把公共冷却误实现成单卡冷却，或者让 CSS 动画脱离模拟时间。
6. 在旧资产路径上直接覆盖不可回滚，破坏其他模式或存档素材引用。
7. 用未实际运行的截图、外部游戏画面、概念图冒充真实浏览器实装结果。

## 12. Codex 完成后的汇报格式

请按以下结构报告：

1. **改造范围**：具体文件/组件/资源及复用或新建情况。
2. **阶段成果**：P0 卡牌与 HUD、P1 档案与设施、P2 扩展各完成到哪里。

5. **回归结果**：命令、通过项、失败项、已知问题，不得仅报告“成功”。
6. **美术债务**：仍缺哪些真正要绘制的精灵/动画/卡面，明确占位与生产建议。
