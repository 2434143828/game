# 给 Codex 的直接开发任务｜v0.3 实时卡牌 + 放置改版

你正在维护用户已有的《网梗收容：奶龙失效》项目。**这是增量补丁，不是新建项目请求。**

1. 先阅读 `01_玩法补丁策划案.md` 和 `config/combat_patch.sample.json`，对比当前项目 v0.2 / 现有代码与配置。先报告哪些组件复用、哪些必须替换；不要清空仓库，不要覆盖用户后来调整过的参数、美术和代码。
2. 补丁冲突项以新策划为准：新主循环是稳定收容物放置产能；**收容物绝不自动失效**，仅玩家主动点击按钮触发；取消旧版每日能量达标推进作为主线；取消旧五个主管技能的独立施放入口，改为 E.G.O. 战斗卡牌。
3. 主游戏形态仍必须是**《脑叶公司》式真正可操作的 2D 设施剖面**。不能开发成按钮/日志驱动的纯网页文字小游戏。保留房间、走廊、员工与收容物在场景中的绘制与行动。
4. **只做一个纵向切片先验收**：奶龙稳定产能 → 点击“主动失效挑战” → 三人自动追敌/普攻 → 九张共享卡组（每把武器3张，卡归属员工）→ 初始3张，每5模拟秒抽1张、手牌上限4 → 成功结算一张卡触发2.5模拟秒全局出牌冷却 → 战术暂停冻结战斗和产能 → 镇压胜利 → 奶龙 I→II、产能增加、E.G.O. 升阶 → 返回设施。
5. 这套卡牌战斗也必须可供外勤抓捕复用。完成 P1 后做一次耄耋外勤抓捕，胜利将其加入设施；失败不增加单位。
6. 先运行现有测试并保留可复用逻辑，之后按策划 P0—P5 做实现。模拟数据只由一个状态树驱动；数值读配置，使用确定性模拟/抽牌随机种子。没有正式资源就使用可替换的 2D 角色和场景占位，禁止 UI 列表假装战斗实体。
7. 每阶段实际执行构建、测试、截图/录屏验收；同步更新 `STATUS.md`，写清已实现、运行过的测试、失败项和素材占位。遇到真实技术阻塞才停下报告，不要只给泛化计划。

请先用不超过十行确认当前工程及受影响文件，**然后直接开发**。优先通过 P1 真实画面和交互验收，而不是先生成五套卡牌页面或概念宣传图。
