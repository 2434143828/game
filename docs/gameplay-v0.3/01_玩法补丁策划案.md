# 《网梗收容：奶龙失效》玩法补丁 v0.3

> 类型：**增量开发补丁 / 玩法结构改版**。适用基线：《网梗收容：奶龙失效》旧版 v0.2 及其后续实际工程。日期：2026-10-23。目标：将原“派遣—压力失效—日目标”循环改为“设施放置生产—主动收容失效升阶—外勤抓捕扩张—实时可暂停 E.G.O. 卡牌战斗”。
>
> 本文是开发规格，不表示程序已经实现。**先扫描当前仓库、对比用户改动，保留可复用代码与素材，不无条件覆盖旧文件**。本补丁涉及的系统优先级高于 v0.2；未提及的美术/基础角色数据等继续沿用旧版。

## 0. 一句话产品定义

**轻量放置收容经营 + 可主动发起的收容物挑战 + 三人队伍实时自动战斗 + E.G.O. 专属卡牌干预。**

玩家平时看一座真正可见的 **2D 设施剖面**，五个收容物被放置在房间内并持续产能；玩家使用能量解锁外勤目标，派三人队伍抓捕新收容物；已经收容的对象可以按按钮**主动失效**，战胜升级挑战后提高其能量产出，解锁更高阶 E.G.O.。战斗中角色自动移动/追踪/普通攻击，玩家以每隔一定时间补充的手牌来进行战术干预，支持**战术暂停**。

**禁止实现成纯文字/卡片按钮结算小游戏。** 档案、卡牌是 UI，但设施、员工、敌人和战斗必须是真正的二维游戏场景与动画。

## 2. 核心成长循环

```
[设施主场景：收容物稳定挂机生产能量]
                  ↓ 领取 / 消费
[外勤目标列表：消耗能量解锁高阶目标]
                  ↓
[三人远征：自动战斗 + 抽牌 + 暂停干预]
                  ↓ 首次抓捕成功
[新收容物入住设施：开放基础产能 + 该物 E.G.O. I]
                  ↓
[主动点击该收容室“开始失效挑战”]
                  ↓ 击败当前升阶形态
[该物阶级 +1 → 产能提高 + E.G.O. 装备/卡牌升级]
                  ↺ 继续积累与挑战
```

两类战斗入口：

1. **外勤抓捕 Capture**：针对尚未拥有的收容物，成功后增加一个新产能单位并开放其 I 阶 E.G.O.。失败不获得该单位。
2. **主动失效 BreachChallenge**：针对已拥有的收容物，**只有玩家点按钮才发生**。成功后此收容物 `rank += 1`，对应能量产出与 E.G.O. 阶级上限提升；失败不升级，也不会被永久删除。

两者 **使用完全相同的三人队伍、E.G.O.、九张卡、抽牌和冷却战斗引擎**；仅进入条件、敌方技能组合、成功奖励不同，不允许维护两套相互矛盾的伤害公式。

### 2.1 首轮内容与开局状态

- 五名对象保持为：**奶龙、耄耋、大狗、叮咚鸡、咕咕嘎嘎**。
- 新档默认**奶龙已收容 I 阶**；其余四个通过外勤依序开放。具体外勤解锁消费在数据配置中设置。
- 为避免开局没有 E.G.O. 而无法凑足九张卡，给予**三套制式训练 E.G.O. 武器**，每套内置三张基础卡；它们是临时教学装备，**不算第六种收容物，也不产能**。
- 正式 E.G.O. 解锁后可以替换任意员工的训练武器。可重复发放训练武器，保证任何三人队伍都有合法卡组；正式 E.G.O. 不需要默认无限复制。
- Demo 首轮建议先开放奶龙、耄耋的捕获/升阶链路，确认可玩后再补全五种；最终目标仍是五种内容。

### 2.2 阶级（Rank）与 E.G.O. 等级

- 每个已收容物的 `rank` 初始为 1，最大阶级按配置，**原型建议 3 阶**；日后可扩为 5 阶，不在第一版一次实现五套不同卡池。
- 首次抓捕：获得 rank1 收容物，并解锁该物的 E.G.O. I 基础武器、防具及三张卡的使用权。
- 每次成功完成当前 Rank 的**主动失效挑战**：只提升**一级**，解锁下一阶 E.G.O. 的属性、卡牌强化和产能倍率。重复打已通过的同一阶不会再次提升等级。
- **每把武器始终提供 3 张卡**，E.G.O. 升阶**强化这三张卡**，而非追加三张，避免三人编队膨胀到 18/27 张。
- 员工配置的是武器与防具的阶级；装备阶级上限受对应收容物进度限制。已经装上的同名装备可随解锁提供升级入口，**不自动在战斗中改变卡组**。
- 装备数值仅做直观属性，特殊功能统一体现在对应三张**战斗卡牌**中；不再单设五个功能性主管技能按钮。

### 2.3 放置产能

- 每个稳定收容物按 `energyPerMinute[rank]` 持续产生能量，按秒结算，可存在小数，UI 只显示合理的小数/整数。
- 未拥有、尚未开放的房间产能=0；处于**主动失效挑战中**的房间产能=0。
- 战斗结束，无论胜负，目标收容物返回稳定态并恢复产能；成功时应用新的 Rank 产能，失败保持原 Rank。不可通过退出/重开骗取挑战胜利。
- 其它稳定收容物在**实时战斗运行**期间继续正常产出，但在**战术暂停**期间整个游戏模拟时间冻结，不能通过长时间暂停刷资源。
- **离线收益**只在无战斗、设施稳定时按离线时间计算，上限原型为 2 小时，可配置。不得离线自动触发失效或自动完成挑战。
- 战斗中退出/刷新：优先恢复战斗检查点；暂时做不到则将挑战判为放弃，取消该次奖励且无离线产能结算。不要把进行中的挑战算成成功。
- 旧版 `producedToday`/日指标不再控制主线；原有 `wallet` 可迁移为总能量余额。保留用户拥有的能量，不要静默清零。

## 3. 实时 E.G.O. 卡牌战斗：唯一战斗引擎

### 3.1 场景与操作

- 一场战斗有 **3 名员工**，敌方一个主要目标（后续可有最多两个分身/小怪）。
- 玩家出战前配备每名员工一把 E.G.O. 武器和一件防具；E.G.O. 武器决定自动普攻的伤害属性、伤害/攻击间隔和该员工贡献的三张卡；防具决定四属性抗性。
- 战斗为**真正的 2D 侧视场景**：人物有站位、位置、移动、攻击动作、受击动作、射程、目标选择；不是仅显示两张血条、放卡牌图标就自动扣血。
- 平时角色**自动寻找/追踪合法目标并普通攻击**，不得强迫玩家不断点敌人。玩家可选定集火目标、下达撤退/防守的基础命令（原型也可先只实现集火）。
- 鼠标/触屏点击卡牌，选择合法目标；卡牌由**该卡所属武器的员工**实际执行。不能把任意卡交给别的员工施放。
- 支持暂停/继续、1x/2x；暂停中查看敌人意图、查看卡牌、选目标，允许**预备 1 张牌**，恢复时在满足施放条件的第一个逻辑帧执行。不能在暂停时连续无消耗施放九张牌。

### 3.2 卡组与冷却基础值（原型默认）

| 参数 | 默认值 | 说明 |
|---|---:|---|
| 小队规模 | 3 人 | 每人 1 把武器 |
| 每把武器供牌 | 3 张 | 由武器档案/阶级决定具体效果 |
| 共享牌库 | 9 张 | 三把武器各提供3张，重复武器允许重复牌但所有卡实例携带各自的 `ownerId` |
| 开局抽牌 | 3 张 | 随机并展示给玩家 |
| 手牌上限 | 4 张 | 未使用卡留手 |
| 自动抽牌间隔 | **5.0 秒** | 独立于出牌公共冷却；只在模拟时间流动时推进 |
| 全局出牌冷却 GCD | **2.5 秒** | 任意一张牌效果成功结算后触发，所有卡共用 |
| 每张牌独立冷却 | 无 | 第一版不做，避免双重冷却复杂化 |
| 弃牌与循环 | **牌堆抽完后洗入弃牌堆** | 不是“无限复读同一张”，每轮至少经过抽/弃流程 |
| 敌方预警 | 0.8–1.5 秒 | 每种主要技能提前显示范围/目标（原型范围） |
| 首轮战斗目标时长 | 60–120 秒 | 后续以实测调整，不通过拖慢抽牌硬凑时长 |

**抽牌精确定义**：

1. 开局洗混 9 张，抽 3 张，抽牌倒计时从 5.0 开始。
2. 每隔 5.0 **模拟秒**尝试抽 1 张；若手牌未满，就从抽牌堆取 1 张。
3. 若抽牌堆为空且弃牌堆非空，先将弃牌堆洗回抽牌堆，再抽 1 张；手牌不会被洗入。
4. **手牌已满时停止抽牌倒计时**，不丢弃牌、不储存多次抽牌次数。打出一张后从当前剩余计时继续，不会瞬间补满。
5. 如果所有牌均在手中且手牌已满，仍遵守以上规则。不能因为抽牌堆空就复制出新牌。
6. 同一张卡不能有两个活跃实例被同时使用；抽牌结果只使用固定随机种子，便于回放与测试。

**出牌精确定义**：

1. 合法出牌条件：GCD = 0、牌在手牌、所属员工仍可行动、目标合法、没有已占用的待施放槽。
2. 选择合法牌和目标后生成一条待执行命令；若暂停，则存入唯一预备槽，不扣牌、不启动冷却。
3. 恢复时间或正常运行时，员工执行卡牌动作；需要接近目标的卡允许该员工自动靠近，期间显示“施放中”，不允许再次提交新卡。
4. **效果命中/成功结算**时：该卡进入弃牌堆、GCD 设为 2.5 秒，清除待执行槽。
5. 若施放前目标消失、员工重伤、玩家取消命令：不结算卡牌、不触发 GCD，原牌留手，及时提示原因；取消时不允许无限瞬发多张卡。
6. 暂停时抽牌间隔、GCD、普攻、敌人 AI 与技能持续时间全部冻结。

### 3.3 卡牌与自动普攻的关系

- 自动普攻是基础 DPS：即使玩家整局不出牌，小队也能对低级目标造成伤害。
- 卡牌用于**爆发、打断、减伤、恢复、复制或团队配合**，不替代普攻。
- 减少“空转”：卡牌要么立即改变某个敌人/员工状态，要么形成清晰的可预见强化；避免只写“伤害+3”而无可见表现。
- 为避免玩家只看挂机，首轮 Boss 至少有一招**明显可用卡牌反制**的预警技能；纯自动也许能打赢同级低难关，但主动干预应该明显降低损失或缩短时间。

### 3.4 员工、目标与失能处理

- 敌人自动寻敌，按当前 AI 规则追击最近有效员工；员工默认追击被选中的优先目标，否则就近目标。
- 角色的 HP/SP 与原先红白黑苍白抗性保持统一；员工 SP 归零可进入短时惊慌/不能施牌状态，HP 归零进入重伤/离场；Demo 失败不永久删除员工。
- 某员工重伤后，**属于他的三张卡在当前战斗中全部失效**：手中的牌自动移入本局移除区；牌堆/弃牌堆中的该员工卡在后续洗牌/抽牌时剔除。其他员工牌继续正常循环。
- 为降低挫败，重伤时立刻补抽 **1 张**合法存活员工卡（如有可抽牌），不受普通抽牌冷却限制；每个重伤事件只补一次。
- 任何时候能使用的卡实例，必须来自当前存活员工装备，不能“死人施法”。
- 全队重伤即战斗失败；敌方主目标 HP 归零即结算成功（若存在分身，按该场景胜利规则清理）。

### 3.5 四属性基础规则（沿用而不是再造）

- 红伤：扣生命；白伤：扣精神；黑伤：同时扣生命和精神；苍白：按最大生命比例扣生命。
- 敌方若只有单条镇压生命，则红白黑对这条结算一次，苍白按敌方最大镇压生命百分比结算。
- 防具提供四种承伤倍率；卡牌伤害和自动攻击使用同一个 `resolveDamage`。不能出现卡牌“白伤扣HP”，自动攻击“白伤扣SP”的不一致。
- 首版先不做元素穿透、随机暴击、牌费体系、速度骰、连携拼点、复杂职业转职。

## 4. 五套 E.G.O.：每套武器恰好 3 张卡

以下为**原型卡牌效果方向和建议数值**；只为第一轮手感验证，非经过平衡验证的最终配置。这里把旧主管技能整合为卡牌，不再有原来的独立施法按钮。卡牌名字只作游戏内梗化命名；卡牌规则与视觉为独立原创设计。

| E.G.O. 来源 | 1号卡（伤害/常规） | 2号卡（功能/应对） | 3号卡（爆发/协作） | 原型定位 |
|---|---|---|---|---|
| **奶龙** | **自我介绍**：对白属性单体造成 14 伤害 | **打断复读**：打断目标蓄力并控制 2 秒 | **复制粘贴**：对同目标复制上一张本局成功结算的攻击牌的 50% 伤害，不能复制自己或恢复牌 | 控制 / 复制 |
| **耄耋** | **哈气突袭**：红伤 20 | **炸毛格挡**：自身获得 3 秒减伤 40% | **暴怒反击**：5 秒内受到敌人攻击后向攻击者反击 22 红伤，仅触发 1 次 | 近战反击 |
| **大狗** | **大狗叫**：对小范围敌人造成 12 红伤 | **声波震退**：打断目标蓄力并击退 | **全力嚎叫**：对范围敌人造成 26 红伤，角色前摇更长 | 范围打断 |
| **叮咚鸡** | **消息轰炸**：黑伤 12（敌方只扣一次镇压值） | **紧急通知**：目标下一次攻击延后 2 秒 | **循环播放**：使本队下一张攻击卡伤害 +30%，生效一次 | 干扰强化 |
| **咕咕嘎嘎** | **嘎嘎声波**：白伤 10 | **安抚一下**：恢复单体 18 精神 | **集体安抚**：全队恢复 10 精神 | 支援续航 |

**卡牌预先规划细则**：
- 三套制式训练武器的每套三张卡暂用：普通打击（红伤8）、简易格挡（本体减伤20%持续3秒）、紧急鼓舞（单体恢复6精神），为了保证初始小队可正常构筑。训练卡不能越级替代正式 E.G.O.。
- **复制粘贴**只读取最近一张成功结算、且可复制的攻击牌的记录；记录不存在时灰显并说明原因；复制伤害不视为再次打出原牌，不递归触发复制或出牌特效。
- 任何治疗或护盾效果不允许超过最大生命/精神，保护效果不叠加乘法堆叠。
- E.G.O. 由 I→II→III 升级优先数值提升，部分卡可在 II/III 阶增加短效果，但仍是 3 张/武器。
- 以上效果由 `cardId` 与行为配置驱动；不能每张牌写一段无法复用的 UI if-else。

## 5. 两种战斗关卡与奖励

### 5.1 主动失效升阶

流程：设施点收容室 → 显示当前 Rank、下一阶产出/装备预览与推荐战力 → **确认主动失效** → 进入战斗 → 胜利 Rank+1（只一次），更新产出/E.G.O. 解锁 → 回设施。

- 未点按钮时 **不会失效**；压力条从主循环移除或改成纯展示，不得隐式触发敌人。
- 挑战中目标停产；战斗胜利/失败回到稳定态。
- 主动失效挑战不能打超过该目标的最大 Rank；满阶改为“已完成”或“重复训练”，训练不再升级。
- 同一时刻最多一个遭遇，不得多个房间并发失效。

### 5.2 外勤抓捕

流程：外勤列表选未拥有目标 → 检查能量、前置收容等级或关卡 → 消耗入场能量 → 同一战斗引擎 → 战胜后播放捕获演出并收容 → 新房间开放 Rank1、产能和基础 E.G.O.。

- 外勤失败不可凭空获得目标；重复抓捕已拥有的对象不会复制该单位产能。
- 允许收容等级不够时显示“未开放”和条件，而不是强行让玩家点进去死一次。
- “捕获”暂用击败主目标即判成功，未来如有需要可增加低血量捕获阶段；首版不另做投球/套圈小游戏。

### 5.3 首轮进度默认值（只为测试成长曲线）

| 对象 | 抓捕开放条件 | 抓捕能量消耗 | I/II/III 产能 (能量/分钟) |
|---|---|---:|---|
| 奶龙 | 初始已有 | — | 2 / 4 / 7 |
| 耄耋 | 奶龙达 II | 50 | 3 / 6 / 10 |
| 大狗 | 耄耋捕获 | 130 | 5 / 9 / 15 |
| 叮咚鸡 | 大狗捕获 | 250 | 8 / 14 / 23 |
| 咕咕嘎嘎 | 任意三个收容物达 II | 430 | 12 / 20 / 32 |

这些数字**仅是检查闭环的示意值**，特别需要测“首个抓捕多久可解锁”和“第二次升阶是否重复无聊”。与当前仓库已有平衡数据冲突时，以当前用户调整的配置为准并在变更记录中注明。

## 6. 与当前 2D 设施、美术的关系

- **设施仍是主要经营界面**：显示收容室、走廊、员工正常行动、对象形象、产能速率、当前 Rank、可用 E.G.O. 和主动失效按钮；不能因为改成放置收益就把设施缩成五张文本卡。
- **战斗场景可共用 2D 游戏引擎**，切成一张清晰横版遭遇场地；员工和对象移动、攻击、受伤都发生在场内。绝不做只有双方头像、数值和卡牌列表的简易网页。
- 正常视觉：现代、干净、舒适的新媒体科研设施，科研人员专业自然；失效战斗：特定收容物局部叠加弹幕、评论、推荐流、音波等污染，**不遮挡卡牌、HP/SP、攻击预警和暂停按钮**。
- 战斗主视区建议至少占 60% 屏幕；卡牌手牌区域置底；侧边有三人生命/精神与敌方意图；移动端再优化，不让主场景成为小窗。
- E.G.O. 卡牌可先用单色美术占位，但须有**清晰图标、所属员工颜色/编号、伤害属性、目标类型、冷却状态和可用性说明**。

## 7. 技术与数据改造建议（遵守现有仓库结构）

**建议独立模块**：
- `FacilityProductionSystem`：产能、离线结算与对象稳定/挑战状态。
- `ProgressionSystem`：捕获标记、Rank、E.G.O. 解锁、关卡开放条件。
- `EncounterSystem`：双方角色状态、自动寻敌/移动/普攻、预警、胜负判定。
- `DeckSystem`：根据三人已装备武器构建 9 张实例、牌堆/手牌/弃牌/移除区、抽牌计时。
- `CardCommandSystem`：合法性、唯一预备槽、目标选择、施牌动作、全局冷却与效果执行。
- `CombatView`：2D 战斗画面；UI 不得单独复制一套状态。

**核心状态字段**：

```ts
interface ContainmentProgress {
  anomalyId: string;
  owned: boolean;
  rank: number; // 0 = 未拥有，1..maxRank = 已收容阶级
  state: 'LOCKED'|'STABLE'|'IN_CHALLENGE';
}

interface CombatCardInstance {
  instanceId: string;
  cardId: string;
  ownerId: string;  // 施牌员工
  sourceWeaponId: string;
  tier: number;
}

interface DeckState {
  drawPile: CombatCardInstance[];
  hand: CombatCardInstance[];
  discardPile: CombatCardInstance[];
  exhausted: CombatCardInstance[];
  drawTimer: number;
  globalCooldown: number;
  pendingCast: null | { instanceId: string; targetId: string; requestId: string };
}

interface EncounterState {
  mode: 'CAPTURE'|'BREACH_CHALLENGE';
  targetAnomalyId: string;
  squadIds: string[]; // 长度必须3
  paused: boolean;
  speed: 1|2;
  deck: DeckState;
}
```

**状态同步强约束**：每次绘制的手牌、冷却、角色位置、设施产能都必须读取唯一模拟状态；不能出现“画面卡牌已经使用、后台仍在手牌”或“失效界面说停产、钱包还在加”的分叉。

### 7.1 兼容旧存档

- 读取旧版时先备份，升级存档版本号（例如 `saveVersion: 3`）。
- 将已有收容物映射为 `owned:true, rank:1`（如果当前工程确实有既有拥有状态）；旧版员工生命/精神、装备与钱包尽量保留。
- 遇到无法映射的旧档装备字段，保留原数据备份，显示迁移摘要，不私自删除稀有装备。
- 删除/禁用旧自动失效触发器前要保证场景 UI 状态也转换到 `STABLE` 或安全状态，不能残留永远“失效中”的房间。
- 若只有 v0.2 静态配置、还没有真正旧存档，可只实现迁移适配器和一个兼容测试，不必过度架构。

## 8. Codex 实施顺序：先做可玩纵切，不要先堆内容

### P0 — 现状扫描与保留
识别引擎、旧的游戏循环、设施场景、攻击逻辑、装备与存档；列出复用/替换清单。建立工作分支或备份，修改前先跑已有测试。

### P1 — **唯一优先纵向切片**：奶龙升阶
在现有 2D 设施中保留奶龙房间与员工；奶龙持续产能；点**主动失效**打开三人战斗；三名员工自动攻击；从三把制式/奶龙武器组成九张卡；自动每 5 秒抽牌、成功出牌后触发 2.5 秒公共冷却；支持战术暂停和目标选择；胜利后奶龙 I→II，产能 2→4 且提升装备阶级；回设施继续生产。

**P1 不通过，禁止宣称整个新版已实现。**

### P2 — 外勤抓捕
做“耄耋首次抓捕”，重用同一场战斗/卡牌/四属性结算引擎；成功后设施增加耄耋房间产能及其 E.G.O. I；失败不发放。

### P3 — 五种 E.G.O. 与首轮配置
补齐五套武器各三牌、训练武器、三种 E.G.O. 阶级升级、五个收容物的可用战斗行为，并验证每种牌能被正确触发和结算。

### P4 — 放置存档与 UI 美术
补离线收益上限、战斗中退出恢复策略、进度显示、装备升级面板、抽牌冷却/GCD 双反馈、战斗预警与平台污染层。优先使用现有资源，缺失素材做可替换 2D 绘制占位。

### P5 — 平衡与验收
跑自动化场景测试、实际打开游戏测试；调小队输出、目标血量、抽牌速度、卡牌频率、抓捕消费与产能增长。至少录制/截取 P1 和 P2 的真实画面及关键步骤。

## 9. 验收清单（必须可在真游戏中观察）

- [ ] 不点击主动失效时，奶龙连续运行十分钟不出现失效；旧压力触发器已停用。
- [ ] 稳定时持续产能，进入失效挑战时该对象产能立即为 0；结束挑战后按当前 Rank 恢复。
- [ ] 刷新/失败不能偷偷完成升阶；同一阶胜利不会叠加多级。
- [ ] 2D 设施真实显示房间、走廊、员工与收容物；不是单页卡片大厅。
- [ ] 点击收容室能看到 Rank、E.G.O. 与失效挑战按钮，只有确认后才进入战斗。
- [ ] 三员工在 2D 战斗场景中自动接敌、移动、普通攻击；敌人会追击/蓄力/造成实际伤害。
- [ ] 每员工装备一件武器且严格提供三张卡；三人牌库恰好九张；重复武器不会搞混 ownerId。
- [ ] 开场手牌三张、牌上限四张、每五秒自动抽一张；满手不烧牌也不积攒待抽次数。
- [ ] 公共出牌冷却 2.5 秒；冷却中第二张卡不能触发；抽牌计时独立不重置。
- [ ] 战术暂停会冻结 AI、移动、抽牌计时、公共冷却、攻击与设施收入；暂停预备的一张卡只在恢复后执行一次。
- [ ] 一张牌必须由对应 ownerId 员工执行；所属员工重伤则对应卡全部失效并被移除。
- [ ] 抽牌堆耗尽后从弃牌重洗，不复活已移除的卡；不能凭空无限复制卡实例。
- [ ] 四属性自动攻击与卡牌使用同一伤害计算；目标失效或选择非法不扣牌、不触发 CD。
- [ ] 外勤失败不给目标；首次成功后该对象入设施、开放产能与 E.G.O. I，重复抓捕不复制。
- [ ] 战斗结束后游戏回到可操作 2D 设施，画面不是结算文字永久替代主场景。
- [ ] 操作性强的低阶战斗约 60–120 秒且至少有一次卡牌能明显反制敌方预警（需要试玩验证）。
- [ ] 保留旧版有效游戏资源、素材与用户代码改动；迁移结果有记录，旧资源没有无故清零。
