# 素材、文案与占位交付｜v0.1

## 1. 当前资源状态

本包没有正式角色图、动画、角色原声或背景音乐。五个收容物名称已确定，具体形象需以后提供参考；当前只要求标号和名称足够清晰、五种轮廓易区分。占位图不得标为官方还原。

角色与原声替换必须只改资源映射，不改战斗/作业逻辑。缺少资源不阻塞可玩原型；渲染失败回退编号图标，不导致实体不可选。

## 2. 必要素材

| 内容 | 数量/状态 | 第一版最低要求 |
|---|---|---|
| 收容物 | 5个，待机/作业反应/失效/移动/蓄力/受击/受控/镇压 | 同一轮廓使用位移、缩放和明暗区分状态；N04静止也需蓄力反馈 |
| 奶龙分身 | 复用N01 | 较小且标“分身”，主样本始终明显 |
| 员工 | 1个基底、6个编号 | 待机、移动、工作、攻击、惊慌、重伤；武器/防具用清楚色标区分 |
| 地图 | 1张、5室+走廊+安全室 | 地图结构与固定路径一致，入口/安全区清楚 |
| 武器/防具图标 | 各6个（含制式） | 图标和红白黑苍白标签同时显示，不靠形状猜参数 |
| 技能图标 | 5个 | 键位/消耗/锁定/冷却信息不互相遮挡 |
| 攻击与技能效果 | 10类左右 | 四伤害颜色+不同小符号、范围预警、击退、恢复、控制、能量入账 |
| 声音 | 6类提示 | 完工、失效、命中、技能、重新收容、日结算；原创程序提示音即可 |

背景音乐不是验收前置条件。玩家第一次交互后才尝试播放音效，有总音量与静音；无法播放时保留视觉反馈，不报阻断性错误。

## 3. 显示文案

界面优先读取config/localization.zh-CN.json。档案正文在anomalies.json；技能正文在skills.json；日简报在days.json。不要把同一句描述复制到多个代码文件。

关键说明始终可查：

“可用能量用于购买与施法；今日累计产能用于达标。”

“该收容物已停止产能。镇压后恢复正常工作。”

“装备仅提供伤害参数与承伤倍率；功能效果位于技能栏。”

“本版只保留日初存档，重试会回退本日的产出和购买。”

数字型装备面板标“承伤倍率”，并展示“0.6× / 受到60%伤害”，不要同时把0.6写成“减伤60%”。苍白标“最大生命比例”，不是“真实伤害”。

## 4. 各物工作/失效文案口吻

奶龙：“它不反对沟通。它只希望下一句话仍然由它决定。”工作规则的精确数字另放系统说明，不让文学表述代替操作规则。

耄耋：“更换工作人员不代表它更喜欢下一位。只代表上一位暂时安全。”

大狗：“上一项工作结束，不等于它已经准备好下一项。”

叮咚鸡：“请先确认这条通知是否需要被播放。”

咕咕嘎嘎：“沉默不是稳定。请检查上次接待记录。”

以上为可用的原创档案题记，不说明现实梗起源，不额外创造玩家必须遵守的隐藏机制。

## 5. 禁止混入宣传片规则

此前概念宣传片中的“预录资料开始等你”“请勿代答”“新增载体”可以用于以后单独的过场或宣传，但本Demo不采集语音、不要求玩家复述、不把输入中文口令作为胜负条件，也不伪装电脑系统通知。

暂停、退出、音量、存档提示保持可靠。界面被污染的效果不进入本版需求。

## 6. 美术升级接口

对每个资源记录assetId、来源记录、是否占位与当前替换状态。正式资源只需替换manifest（资源映射表）并保证同样的状态名和锚点。碰撞、射程、路径取配置，不随图片尺寸漂移。

不要求在本阶段生成概念海报、宣传片、角色立绘或独立官网。先完成可操作游戏再决定额外视觉投入。
